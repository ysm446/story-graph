- 2026-07-26 05:40 **登場と退場を LLM の判断から外した**(ユーザー提案)。
  - **登場**: `char_introduce` を廃止し、**ノードの cast から導出**する方式に変更(`fold(state, events, cast)` が cast のキャラを未登場なら初登場として作る)。同じ情報を二重に持つのをやめたので、重複した introduce・退場済みキャラの蘇生・島を繋いだときの掃除といった問題が**構造的に起きなくなった**。`_ensure_cast_introduced` と冗長 introduce のフィルタは削除。検証からも「char_introduce 前のキャラが cast に…」を削除。既存データの introduce イベントは無害だが、右クリックの「整合を取る」で掃除できる
  - **退場**: `char_retire` も LLM スキーマから外し、**作者が UI で設定**する。シーンエディタの Cast チップに **⊗**(このシーンで退場。理由を入力)と **⏎**(取り消し)を追加。退場済みキャラを後のシーンの cast に入れると従来どおり検証で警告が出る
  - LLM が発行できるのは `memory_add` / `relationship_update` / `fact_set` の 3 種だけになり、スキーマの枝が減って文法制約付き生成も軽くなった。EVENT_RULES からも 2 行削除
  - 12B 実機で確認: 「アヤは去っていく」という本文でも `char_retire` が出ず(以前は誤判定の実績あり)、登場状態は cast から導出されて検証もクリーン
  - `state_cache` の妥当性キー(`input_hash`)に cast を含めるようにした(cast を編集したら再 fold されるように)

- 2026-07-26 05:10 島を繋いだ直後の処理を「LLM で作り直す」から「**整合を取る(LLM なし)**」に変更。状態は fold が親から積み直すので**再抽出は本来不要**で、実害があるのは上流で登場済みのキャラへの `char_introduce` が残ること(退場済みキャラに当たると `retire_reason` が消えて「蘇生」する)だけ。そこで `POST /nodes/{id}/normalize_chain` を追加し、接続時に**重複した登場イベントの削除と検証だけ**を即時実行するようにした(親から順に処理するので、上流を掃除した結果が下流の判定に反映される)。LLM による作り直しは、関係値の delta や記憶の文面を新しい文脈に合わせたいときの**任意操作**として、右クリックメニューとインスペクタのボタンに残す(ラベルに「LLM」と明記)。右クリックメニューにも「整合を取る(LLM なし)」を追加。

- 2026-07-26 04:50 構造モードに**右クリックメニュー**を追加。範囲選択した複数シーンに対してまとめて実行できる:
  - **イベントを作り直す**(選択したシーンだけ)/ **この先も**(選択 + 下流すべて)。`POST /nodes/reextract`。抽出は親の状態を前提にするので、選択順がばらばらでも**ルートからの深さ順に並べ替えて逐次実行**する
  - **清書(未清書のみ)** / **清書し直す(上書き)**。条件は**鑑賞モードで選んだスタイルプリセットと POV をそのまま使う**(`reader_preset_id` / `reader_pov_char` は既に settings に保存されている)。メニューには使用する条件を表示する。`POST /render` に `node_ids` と `skip_existing` を追加し、清書は直前シーンの散文に接続するため正史順に並べ替えて逐次実行する
  - **まとめて切り離す** / **まとめて削除**(いずれも件数つきの確認ダイアログ)
  - 進捗は左上に表示し中止でき、処理中のシーンは枠が光る(単発の処理と同じ扱い)
  - 右クリックしたノードが選択に含まれていなければ、そのノード単体を対象にする

- 2026-07-26 04:20 LLM 処理中のノードの枠が時計まわりに光るようにした。`@property --sg-angle` で conic-gradient の角度をアニメーションさせ、mask で枠線部分だけを残す方式(`.node-busy-ring`)。点灯するのは **シーン生成中(続きを書く元のノード)** / **イベント抽出中のノード** / **チェーン再抽出でいま処理しているノード**(逐次実行なので常に1つずつ移動する)。処理の対象がどこかが一目で分かる。

- 2026-07-26 04:00 ツールバーに「⊕ 独立シーン」を追加。どこにも繋がらないシーンを**画面の中央**に作る(`POST /nodes` の `detached`)。正史は伸びず status は draft。作ったノードを選んで「+ シーン」で足していけば島がそのまま育ち、あとでハンドルのドラッグで本編に繋げる。中央配置は手動配置として保存するので、自動レイアウトに引っ張られない。従来の「+ シーン」(選択ノードの子 / 未選択なら正史の末尾)は変更なし。

- 2026-07-26 03:40 **ノードのエッジを切断・接続できるようにした**(まとまったエピソードを島として作り置きし、後から本編に繋ぐため)。
  - 切断: エッジをクリックして Delete、またはダブルクリック。そのシーン以下が独立した島になる(シーンは消えず、島の内部構造も保たれる。`POST /nodes/{id}/detach`)。島は正史から外れるので status は draft、story_order も貼り直す
  - 接続: ノードのハンドルをドラッグして親子を繋ぐ(`POST /edges`)。繋げるのは「島の根(親がいないノード)」だけで、多重親と循環はガードする。既定は draft で接続し、正史にするのは従来どおり「★ このブランチを正史にする」
  - 島は自分の根から fold されるので、繋ぐまでは上流の状態を引き継がない(単独で書けて、繋いだ瞬間に前提が変わる)
  - **チェーン再抽出**: 接続直後に「この先 N シーンのイベントを作り直しますか?」と聞く。インスペクタの「⟳ ここから先のイベントを作り直す」からも実行できる。親から子の順に逐次抽出し(各シーンは親の新しい状態を前提にするため)、進捗表示と中止に対応(`POST /nodes/{id}/reextract_chain`、SSE)
  - 再抽出は破壊的なので、**手動で足したイベント(source=user)は既定で残す**。抽出結果と同一内容のものは重複させない
  - 上流で既に登場済みのキャラへの `char_introduce` は抽出時に捨てるようにした(重複の解消と、退場済みキャラが「蘇生」する事故の防止)
  - 12B 実機で「本編2シーン + 島2シーンを接続 → チェーン再抽出」を確認
