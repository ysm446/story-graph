# キャラクターカードの形式

作成日時: 2026-11-10 18:10
更新日時: 2026-11-10 19:33

story-graph のキャラクターを、**ある時点の状態ごと** 1 つのファイルに書き出すための形式。
書き出したカードは、ほかのアプリが読み込んで使う。読む側は特定のアプリに限らない。
最初の読み手は音声会話アプリ story-graph-voice-chat(`D:\GitHub\story-graph-voice-chat`)。

- **この文書が正本。** 読む側のリポジトリにはコピーを置き、先頭に「正本は story-graph の
  `docs/reference/character-card-format.md`、形式の版は 1」と書く。
- **状態(2026-11-10)**: story-graph の書き出しは実装済み。ただし `summary` と `examples` はまだ出さない。
  読み込み(読む側)は未実装。書き出しの設計は [docs/design/character-card.md](../design/character-card.md)。
- 書く側の決まりは §2〜§5、読む側の決まりは §6。読み込みを実装する人は §2〜§6 を読めば足りる。

## 1. 考え方

1. **一方向。** story-graph が書き、ほかのアプリが読む。読む側は story-graph のライブラリにも
   カードにも書き戻さない。読む側で起きたこと(会話など)は物語に影響しない。
2. **カードは 1 時点の写し。** 「キャラクター」と「どのシーンまでの状態か」の組で 1 枚。
   同じキャラクターでも時点が違えば別のカードで、読む側は別のキャラクターとして扱う。
3. **中身は文章で持つ。** story-graph のイベント・関係値・記憶の ID などの内部構造は入れない。
   読む側は story-graph の仕組みを知らなくてよい。
4. **本人が知っていることだけを入れる。** 他のキャラクターの内面、本人が居合わせなかった出来事、
   選んだ時点より先の出来事、設定資料(作者向けの資料)は入れない。
5. **長さは読む側が詰める。** カードは文字数の上限を持たない。その代わり、配列は重要な順に並べる(§3)。
6. **読む側を選ばない。** カードはキャラクター本人のことだけを書き、使い道(音声会話、文字のチャット、
   画像生成、別の執筆ツールなど)を決めない。特定のアプリ・モデル・TTS エンジンでしか意味を持たない項目は入れない。
   `card.json` だけでカードとして成り立ち、画像と声は付属物。扱えない読む側は無視してよい。

## 2. 入れ物

zip ファイル 1 つ。拡張子は `.zip`。中身をそのまま展開したフォルダも同じカードとして扱う。

```
ゆきこ@雨の駅の直後.zip
  card.json            必須。zip の直下に置く(フォルダで包まない)
  images/avatar.png    任意
  images/reference.png 任意
  voice/ref1.wav       任意
```

- `card.json` は UTF-8(BOM なし)。
- カードが参照するファイルは、すべて同じ zip の中に相対パスで置く。区切りは `/`。
- ファイル名は書き出し時の表示用で、意味を持たない(識別は §4 の `source` で行う)。
- 画像・音声は元のファイルをそのまま入れる(再圧縮しない)。
  画像は png / jpg / webp、音声は wav / mp3 / flac / ogg。

## 3. card.json

```json
{
  "format": "story-graph-character-card",
  "version": 1,
  "language": "ja",
  "source": {
    "app": "story-graph",
    "app_version": "0.1.0",
    "character_id": "3f9a1c0b7d2e",
    "node_id": "a81c44e0f6b2",
    "library": "雨の町",
    "label": "「雨の駅」の直後",
    "exported_at": "2026-11-10 18:10"
  },
  "name": "ゆきこ",
  "reading": "ゆきこ",
  "profile": "面倒見がよく、頼まれると断れない。自分の弱みは人に見せない。",
  "appearance": "二十代後半の女性。肩までの黒髪、紺のコート。",
  "speech": "落ち着いた丁寧語。親しい相手には語尾がくだける。",
  "situation": [
    "町の図書館で司書をしている",
    "弟の行方を一人で探している"
  ],
  "world": [
    "町では三か月前から雨が止んでいない"
  ],
  "relationships": [
    { "name": "ポチ", "appearance": "茶色の柴犬", "feeling": "深い信頼・愛情「家族」" },
    { "name": "佐伯", "appearance": "四十代の男性。駅員の制服", "feeling": "やや警戒" }
  ],
  "memories": [
    { "text": "駅のホームで弟の傘を見つけた", "when": "今日" },
    { "text": "佐伯が弟の話になると目を逸らした", "when": "3日前" },
    { "text": "子どもの頃、弟と川で溺れかけた" }
  ],
  "summary": "弟を探して三か月。今日、駅で弟の傘を見つけ、駅員の佐伯が何か隠していると疑い始めた。",
  "examples": [
    "「大丈夫です。慣れていますから」",
    "「……ポチ、あんたは何か見たの?」"
  ],
  "images": [
    { "file": "images/avatar.png", "role": "avatar" },
    { "file": "images/reference.png", "role": "reference" }
  ],
  "voice": {
    "caption": "大人の低い落ち着いた女性の声",
    "seed": 42,
    "refs": ["voice/ref1.wav"]
  }
}
```

### 項目

必須は `format` / `version` / `source` / `name` だけ。ほかは無ければ項目ごと省く
(空文字・空配列・`null` を書かない)。

| 項目 | 型 | 中身 |
|---|---|---|
| `format` | 文字列 | `"story-graph-character-card"` 固定 |
| `version` | 整数 | 形式の版。この文書は `1` |
| `language` | 文字列 | 文章の言語(BCP 47。日本語は `"ja"`)。省いたら不明 |
| `source` | オブジェクト | どのキャラクターの、どの時点の写しか(§4) |
| `name` | 文字列 | 名前 |
| `reading` | 文字列 | 名前の読み(ひらがな) |
| `profile` | 文字列 | 人物像・性格。時点で変わらない設定 |
| `appearance` | 文字列 | 外見 |
| `speech` | 文字列 | 口調・話し方 |
| `situation` | 文字列の配列 | その時点の本人の状況。1 要素に 1 つの事柄(文でも「項目: 内容」の形でもよい) |
| `world` | 文字列の配列 | その時点で世間に知られていること。書き方は `situation` と同じ |
| `relationships` | 配列 | 他のキャラクターへの、その時点の気持ち |
| `relationships[].name` | 文字列 | 相手の名前。必須 |
| `relationships[].appearance` | 文字列 | 相手の見た目(人か動物かが分かる程度の短い文) |
| `relationships[].feeling` | 文字列 | 相手への気持ち。必須 |
| `memories` | 配列 | 本人が覚えている出来事 |
| `memories[].text` | 文字列 | 出来事。1 文。必須 |
| `memories[].when` | 文字列 | カードの時点から見ていつのことか(「今日」「3日前」)。分からなければ省く |
| `summary` | 文字列 | いまの本人を短くまとめた文章(経緯と、いま気にかけていること)。400 字が目安 |
| `examples` | 文字列の配列 | 口調の手本になる本人の台詞 |
| `images` | 配列 | 画像(§5) |
| `voice` | オブジェクト | 声(§5) |

### 並び順

`situation` / `world` / `relationships` / `memories` / `examples` は**重要な順**に並べる。
読む側が長さを詰めるときは、後ろの要素から落とす。`memories` は時系列順ではない
(時期は `when` で示す)。

### 入れないもの

- 数値(関係値、記憶の重要度など)。`feeling` のように文章にして入れる。
- 話し相手が誰か、どんな場面で話すか。カードは本人のことだけを書き、会話の枠組みは読む側が決める。
- 特定の TTS エンジンだけで意味を持つ設定(エンジン側の声 ID、追加パラメータ)。

## 4. source — カードの身元

| 項目 | 中身 |
|---|---|
| `app` | 書き出したアプリの名前。story-graph は `"story-graph"` |
| `app_version` | 書き出したアプリのバージョン |
| `character_id` | story-graph でのキャラクターの ID。必須 |
| `node_id` | 写した時点のシーンの ID。必須。そのシーンが終わった直後の状態を表す |
| `library` | ライブラリの名前(表示用) |
| `label` | 時点を人が読める形で書いたもの(表示用)。書き出し時に作者が直せる |
| `exported_at` | 書き出した日時。`YYYY-MM-DD HH:MM` |

**カードの同一性は `character_id` と `node_id` の組で決まる。**
それ以外の項目は表示と確認のためのもので、同一性の判定には使わない。

## 5. 画像と声

### images

| 項目 | 中身 |
|---|---|
| `file` | zip 内の相対パス。必須 |
| `role` | 用途。必須。`avatar`(顔のアイコン。正方形に切り抜き済み)/ `reference`(全身などの参照画像) |

同じ `role` が複数あるときは、先頭が代表。知らない `role` の画像は、読む側は使わなくてよい。

### voice

| 項目 | 中身 |
|---|---|
| `caption` | 声の説明文(性別・年代、高さと質感、話す速さと調子) |
| `seed` | 声を固定するための整数 |
| `refs` | 参照音声の、zip 内の相対パスの配列 |
| `speed` | 話す速さの倍率(1.0 が標準)。story-graph は声ごとの速さを持たないので、書き出しでは省く |

`caption` と `refs` はどちらか一方でも両方でもよい。両方あるときは、参照音声の声に説明文の話し方を重ねる。
`voice` が無いカードは、読む側の既定の声で話す。

## 6. 読む側の決まり

1. **書き戻さない。** カードのファイルも story-graph のライブラリも変更しない。
   読み込みはコピーで、読み込んだあとの編集は読む側のデータだけに行う。
2. **版の確認。** `format` が違うもの、`version` が読む側の対応より大きいものは、
   理由を示して読み込みを断る。
3. **知らない項目は無視する。** 版 1 のまま項目が増えることがある。
   カードをそのまま厳格な型で検査せず、知っている項目だけ取り出す。
4. **同一性。** `source.character_id` と `source.node_id` の組が同じカードは同じキャラクター。
   - 組が新しい: 新しいキャラクターとして追加する。同じ `character_id` で `node_id` が違うカードも
     別のキャラクターで、会話の記憶を共有しない。
   - 組が既にある: 設定(文章・画像・声)を新しいカードの内容に更新し、会話の記憶は残す。
     読む側で手を入れた設定を上書きすることになるので、更新の前に確認を出す。
5. **表示名。** 一覧では `name` に `source.label` を添えて、時点の違うカードを見分けられるようにする。
6. **長さを詰める。** 読む側の上限に収まらないときは、配列の後ろから落とす。文の途中では切らない。
   `summary` があり、`memories` を載せきれないときは、`summary` を優先して載せる。
7. **zip の展開。** 展開の前に全エントリのパスを確認し、絶対パス・`..` を含むもの・
   展開先の外を指すものが 1 つでもあれば読み込みを断る。`card.json` が参照していないファイルは取り込まない。
8. **欠けていても読む。** 参照されている画像・音声が zip に無い場合は、そのファイルだけを飛ばし、
   飛ばしたことを知らせる。

### 参考: story-graph-voice-chat の現在の項目への写し方

読む側の一例。形式の一部ではなく、読む側の都合で変えてよい。現在の `backend/characters.py` の `Character` に写す場合の目安。

| カード | Character | 備考 |
|---|---|---|
| `name` / `reading` | `name` / `reading` | |
| `appearance` | `profile` | |
| `profile` | `personality` | |
| `speech` | `style` | |
| `examples` | `examples` | 改行でつなぐ |
| `situation` | `situation` | |
| `world` / `relationships` / `summary` / `memories` | `background` | この順に載せ、上限で `memories` の後ろから落とす |
| `voice` | 声プロフィールを新規作成して割り当てる | |

## 7. 書く側の作り方

story-graph での作り方は [docs/design/character-card.md](../design/character-card.md) に書く。
各項目を story-graph のどのデータから作るか、どの段階で何を入れるかはそちらを見る。
この文書は形式だけを決め、作り方には立ち入らない。

## 8. 版の扱い

- 項目を足すだけの変更は `version` を上げない(読む側は知らない項目を無視する)。
- 既存の項目の意味や型を変える、必須項目を増やす場合は `version` を上げ、この文書に変更点を書く。
