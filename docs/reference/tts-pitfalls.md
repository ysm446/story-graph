# TTS に変な声を出させないための注意点

作成日時: 2026-11-11 02:06
更新日時: 2026-11-11 02:06

story-graph で音声読み上げを作るあいだに踏んだ失敗と、その対策のまとめ。
ほかのアプリ(最初の読み手は story-graph-voice-chat)が同じ失敗を繰り返さないための資料で、
story-graph の中身を知らなくても読めるように書く。

- 確かめたエンジンは **Irodori-TTS v4-Small**(Irodori-TTS-Server、OpenAI 互換の `POST /v1/audio/speech`)だけ。
  ほかのエンジンでは効き方が違うことがある。エンジンに固有の話には【Irodori】と付ける。
- 数値は story-graph でいま使っている値。実測したものは「実測」と書く。それ以外は聞いて決めた目安。
- 実装は [backend/voice.py](../../backend/voice.py) と [backend/tts.py](../../backend/tts.py)、
  経緯は [docs/design/voice.md](../design/voice.md)。

## 0. いちばん効くもの

急ぐときは、この 5 つだけ先に入れる。

1. **声に出ない文は TTS に渡さず、間にする**(§1.1)。妙な音の原因でいちばん多い。
2. **seed を固定する**(§3.1)。固定しないと 1 文ごとに別人の声になる。
3. **気に入った声は参照音声にして固定する**(§3.2)。説明文だけの声は、seed を固定しても文ごとに揺れる。
4. **細かく切りすぎない**(§2.1)。別々に合成した継ぎ目ごとに声色が変わる。
5. **Markdown とコードを外してから渡す**(§1.2)。LLM の返事をそのまま渡すと記号を読む。

## 1. 渡す前に外すもの

### 1.1 声に出ない文は渡さない

「……」「……っ！」「ッ!?」「――」のような文は、息づかいや間であって読む言葉ではない。
そのまま渡すと、TTS が適当な音を当てて崩れる。

- **判定**: 記号・三点リーダ・ダッシュと、**小さい仮名・長音だけ**でできた文は「声に出ない」とする。
  小さい仮名・長音は `っッぁぃぅぇぉァィゥェォゃゅょャュョゎヮゕゖヵヶーｰ〜～`。
  ふつうの仮名・漢字・英数字が 1 字でもあれば読む(「あっ！」「はぁ……」「ん……」は読む)。
- **扱い**: 文・台詞の単位で外し、直前の文のあとの間を 900ms に延ばす。黙って消すと間が詰まって不自然になる。
- **効果音にしようとしない**。「……っ！」を息を呑む音として鳴らす方式(【Irodori】`😮……っ！！` を渡す)を
  5 日ほど使ったが、単独の「っ」を適当な音で読んで崩れることがあり、やめて間に戻した。

```python
import re

_READABLE = re.compile(r"[\w぀-ヿ㐀-鿿]")  # 仮名・漢字・英数字
_SILENT_KANA = set("っッぁぃぅぇぉァィゥェォゃゅょャュョゎヮゕゖヵヶーｰ〜～")

def is_voiceable(text: str) -> bool:
    return any(_READABLE.match(ch) and ch not in _SILENT_KANA for ch in text)
```

### 1.2 Markdown とコード

LLM の返事には Markdown が混ざる。外さないと記号を読んだり、妙な抑揚になったりする。

- コードブロック(``` で囲まれた部分)は**丸ごと読まない**。ストリーミング中は閉じていないブロックも外す。
- 外す記号: 見出しの `#`、引用の `>`、箇条書きの `-` `*` `+` と `1.`、太字・斜体・取り消し線、
  インラインコードの `` ` ``、水平線、表の区切り行。
- リンクと画像は、表示される文字だけ残して URL を捨てる。
- 表のセルの区切り `|` は「、」に置き換える(消すとセルの中身がつながって読まれる)。

### 1.3 ト書き

キャラクターの返事に混ざる「（少し視線を外して）」のようなト書きは、キャラの声で読むとおかしい。

- **全角の（）だけ**をト書きとして扱う。半角の () は顔文字や補足にも使われるので、ト書きとは限らない。
- 読まないか、別の声(語り手)で読むかを選べるようにする。「（〇〇な表情で）台詞」が続くと、
  読んだ場合に台詞の流れが切れる、という声があった。音声会話なら**読まないのが無難**。
- ストリーミングでは、**（）の途中で切って渡さない**。閉じていない切れ端はト書きと見分けられず、
  キャラの声で読まれてしまう。

### 1.4 エンジン向けの記号を保存しない

【Irodori】感情は文の先頭の絵文字で指定する。この絵文字は**送る直前に付けて捨てる**。
会話の履歴や台本に残すと、画面に出たり、次のターンで LLM が真似して返事に絵文字を混ぜたりする。
逆に、LLM の返事に絵文字が混ざっていると、意図しない演技の指定として効いてしまうので、
返事の絵文字は渡す前に外すか、プロンプトで書かせないようにする(story-graph では未対策。会話アプリでは要注意)。

## 2. 切り方

### 2.1 細かく切りすぎない

文を 1 つずつ別々に合成すると、継ぎ目ごとに声色が少し揺れる。継ぎ目を減らす。

- 地の文・説明の文は、続く文を **100 字まで**まとめて 1 回で合成する。段落はまたがない。
- 台詞は 1 つをそのまま 1 回で合成する。**160 字**を超えるときだけ文末で割る
  (長すぎると最初の音が出るまでが遅くなる)。
- 文末は `。！？!?` の連なり。「……!?」の途中や、閉じ括弧の直前では割らない。

### 2.2 ストリーミングの返事

返事が書き上がるのを待たずに読むときの決まり。

- **最初の 1 文はすぐ渡す**(待たせない)。2 文目からは、読める所が **80 字**溜まってから渡す(継ぎ目を減らす)。
- 切ってよい場所は、文末・改行・閉じ括弧の直後だけ。**括弧の中とコードブロックの中では切らない**。
- 合成は再生より 3〜5 倍速い(実測。12〜33 字で 1.0〜1.8 秒、音声は 2.7〜8.3 秒)ので、
  2 つ先まで先に合成しておけば途切れない。【Irodori】サーバーは 1 件ずつ合成するので、それ以上積んでも速くならない。

### 2.3 文の途中の「」で切らない

「」を見つけるたびに台詞として切り出すと、強調や引用(「約束」という言葉、「田村工業」から、など)で
文が 3 つに割れ、継ぎ目ごとに声色が変わる。**台詞らしい「」だけ**を切り出す。条件は両方。

1. 文の頭で始まる(段落の頭か、直前が `。！？` か別の「」の閉じ)。
2. 閉じたあとが台詞らしい(段落の終わり・次の「」・句読点、または「と言った」の「と」)。
   「という」「といった」「とは」「とか」「との」「として」「って」や助詞が続くなら名詞句として扱う。

小説の本文を読ませないアプリ(返事がすべて本人の発言)なら、「」を特別扱いしないほうが単純で安全。

## 3. 声を揺らさない

### 3.1 seed を固定する

説明文(caption)で声を作るエンジンでは、seed が変わると別人の声になる。
**合成のたびに同じ seed を送る**(story-graph の既定は 1234)。気に入った声は seed ごと保存する。
キャラクターカードの `voice.seed` はこのための値なので、読み込んだらそのまま使う。

### 3.2 参照音声で固定する

seed を固定しても、説明文だけの声は**読む文が変わると声の細部がずれる**。
対策は、気に入った試し読みを参照音声にして固定すること。

- 実測(4 文の声の高さの中央値): 説明文だけ 172 / 155 / 190 / 203 Hz(幅 47 Hz)→
  参照音声で固定後 138 / 145 / 138 / 134 Hz(幅 11 Hz)。
- 説明文は残してよい。声質は参照音声、話し方は説明文が決める。
- 参照音声は **wav** で渡す(TTS サーバーが opus を参照音声として読めるとは限らない)。
- カードに `voice.refs` があれば、それを優先して使う。

### 3.3 手本にする音声の選び方

手本の話し方は、その後の読み全体に移る。参照音声にする文は次を満たすものにする。

- 10〜15 秒(8 秒未満は短い)。
- 感情を込めない、平らな調子。
- いろいろな音を含む、ふつうの文。
- 「……」、ささやき、叫びを入れない。
- 【Irodori】会話で使う声は、**台詞の調子**で読ませた音声を手本にする。story-graph では「」付きの文を
  会話調、「」なしの文をナレーション調(先頭に 📖)で読ませていて、ナレーション調を手本にすると会話も朗読調になる。

### 3.4 話者を替えるときに読み上げの列を作り直さない

複数のキャラが続けて話すとき、発言ごとに再生の列を作り直すと、前の人の読み上げを止めてしまい、
最後の発言しか聞こえない。列は 1 本のまま、声の主だけを替える。

## 4. 読み間違い

漢字の名前や固有名詞は読み間違える。**合成の直前に、読み(ひらがな)へ置き換えて渡す**。
画面の表示と会話の履歴は漢字のまま。

- 「名前(読み)」の形で書き添えない。TTS は括弧の中も読むので、2 回読む。
- **長い語から先に置き換える**(「山崎誠」より先に「山崎」が置き換わらないように)。
- 姓だけ・名だけの読みも登録すると便利だが、**1 文字の語は登録しない**
  (「誠」を登録すると「誠実」まで読みが変わる)。
- キャラクターカードの `reading` は名前の読み。名前が空白で区切られていて(「山崎 誠」)、読みも同じ数に
  区切られていれば、続け書き・姓だけ・名だけの読みを作れる。
- キャラでも場所でもない語(会社名・用語)のために、利用者が足せる読み辞書を持つとよい。
- 音声をキャッシュするなら、読みを置き換えた**あと**の文を鍵にする(読みを直したら作り直されるように)。

## 5. 感情の付け方

【Irodori】感情は絵文字で指定し、同じ絵文字を 2 つ重ねると強まる。story-graph の対応表:

| 感情 | 絵文字 | 感情 | 絵文字 |
|---|---|---|---|
| joy | 😊 | whisper | 👂 |
| sad | 😟 | shout | 💥 |
| anger | 😠 | laugh | 😆 |
| fear | 😰 | cry | 😭 |
| surprise | 😲 | 地の文(感情なし) | 📖 |

- **付けすぎると大げさになる。** LLM に感情を選ばせたら、地の文の 7 割に感情が付いて読みが芝居がかった(実測)。
  「はっきりしないときは neutral」「強さはふつう 0.5、はっきり強いときだけ 0.8 以上」と締めて使う。
  絵文字を 2 つ重ねるのは 0.8 以上のときだけ。
- 感情は固定の語彙から選ばせ、LLM に文そのものを書き直させない(文が欠けたり変わったりする)。
  知らない語が返ってきたら neutral として扱う。
- 対応表と 📖 の効き方は、まだ十分に聞き比べていない。
- 会話の返事に感情を付けるには LLM をもう一度呼ぶことになり、返事が遅れる。story-graph のチャットでは付けていない。

## 6. 再生の側でやること

- **間は合成せず、再生の側で空ける。** 文のあと 250ms、段落のあと 600ms、声に出ない文のあと 900ms。
  会話の返事では最大 600ms に詰めている。「……」を渡して間を作らせない(§1.1)。
- **速さは再生の側で変える**(`playbackRate` と `preservesPitch`)。TTS に速さを指定して作り直すと、
  速さを変えるたびに全部を合成し直すことになる。間も同じ割合で縮める。
- TTS サーバーが止まっていると、最初の 1 文が十数秒遅れる(実測 16 秒)。声を使うと分かった時点で先に起こしておく。

## 7. まだ分かっていないこと

- Irodori 以外のエンジンで、どの対策が要る / 要らないか。
- LLM の返事に混ざった絵文字・顔文字・英字・数字・URL の読まれ方(story-graph では系統立てて確かめていない)。
- 笑い声や相づち(「ふふっ」「えっと……」)の崩れやすさ。いまは仮名があるので読ませている。
