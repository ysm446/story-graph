# 取り込み JSON の書き方

作成日時: 2026-10-14 02:32
更新日時: 2026-10-14 02:55

story-graph に物語を取り込むための JSON ファイルの仕様。**このファイルを書く人(または LLM)向けの文書**で、
これだけ読めば書けるようにしてある。設計の背景は [docs/design/import-json.md](../design/import-json.md)。

- 完成例: [import-example.json](import-example.json)(4 シーンの短い話。全部の項目を使っている)
- 書いたら、必ず検査コマンドを通す(§8)

## 1. 何を書くか

物語を、次の 6 種類のデータに分けて書く。

| 配列 | 中身 |
|---|---|
| `characters` | 登場人物。名前、人物像、話し方 |
| `places` | 場所 |
| `documents` | 設定資料。世界のルール、組織、用語、時代背景など |
| `scenes` | シーン。**物語の順に、1 本の直列で並べる** |
| `scenes[].events` | そのシーンで、人物が覚えたこと・関係の変化・事実の変化 |
| `chapters` | 章(幕などの大きな区切り)。シーンのまとまり |

一番外側は次の形にする。`format` と `version` はこのとおりに書く。

```json
{
  "format": "story-graph-import",
  "version": 1,
  "title": "作品の名前",
  "characters": [],
  "places": [],
  "documents": [],
  "chapters": [],
  "scenes": []
}
```

決まり:

- **ID は書かない。** 人物と場所は名前で指す。名前は一字一句そろえる(「アヤ」と「あや」は別人になる)
- **ここに無い項目は書かない。** 知らない項目があると検査で誤りになる
- 省略できる項目は、分からなければ省略する。空文字や推測で埋めない
- 必須なのは、`characters[].name`、`places[].name`、`documents[].title`、`scenes[].beat`、`chapters[].title` と `chapters[].scenes`

## 2. characters(登場人物)

| 項目 | 必須 | 内容 |
|---|---|---|
| `name` | ○ | 名前。重複させない |
| `reading` | | 名前の読み(ひらがな) |
| `profile` | | 人物像。性格の基調、背景、物語が始まる前の状況 |
| `appearance` | | 外見 |
| `voice` | | 話し方。一人称、口調、**実際の言い回しの例** |
| `color` | | 色(`#7c5af7` の形)。省略でよい |

- `profile` には、**物語が始まる前のその人**を書く。物語の中で起きることは、シーンのイベントに書く
- `voice` は具体的に書く。この人物と会話するときの話し方は、ほぼここで決まる。
  「丁寧」のような一言ではなく、一人称、語尾、口癖、言い回しの例を入れる
- シーンに一度でも出る人物は、全員ここに書く

## 3. places(場所)

| 項目 | 必須 | 内容 |
|---|---|---|
| `name` | ○ | 名前。重複させない |
| `reading` | | 名前の読み(ひらがな) |
| `description` | | 変わらない設定。地形、規模、成り立ち |
| `atmosphere` | | 雰囲気。匂い、音、光 |
| `color` | | 色。省略でよい |

## 4. documents(設定資料)

人物でも場所でもない設定を書く。世界のルール、組織、用語、時代背景など。

| 項目 | 必須 | 内容 |
|---|---|---|
| `title` | ○ | タイトル。重複させない |
| `category` | | 分類(自由な言葉。「組織」「用語」「歴史」など) |
| `body` | | 本文。Markdown で書ける |
| `status` | | `confirmed`(確定した設定)/ `draft`(構想)/ `reference`(参考資料)。省略時は `draft` |
| `scope` | | この設定が当てはまる範囲や時点(自由な文) |
| `ai_mode` | | AI がどう参照するか。`search`(必要なときに検索。既定)/ `always`(いつも読む)/ `never`(読まない) |

- 原作で決まっている設定は `confirmed` にする
- `always` は、短くて常に効かせたい決まりだけに使う。長い資料は `search` にする

## 5. scenes(シーン)

**物語の順に並べる。** 配列の順が、そのまま物語の順になる。分岐は書けない(1 本の直列だけ)。

| 項目 | 必須 | 内容 |
|---|---|---|
| `title` | | タイトル。章から指すときに使うので、付けておく |
| `key` | | タイトルが重なるときの目印(自由な短い文字列)。重複させない |
| `beat` | ○ | シーンの本文。**そのシーンで起きる出来事**を数文で書く |
| `emotional_core` | | そのシーンを貫く感情を一言で(例: 「言えなかった別れ」) |
| `cast` | | その場に居る人物の名前の配列。主な人物から並べる |
| `location` | | 場所の名前。前のシーンと同じなら省略してよい(引き継がれる) |
| `elapsed` | | 前のシーンからの経過(§5.1) |
| `events` | | そのシーンで起きた変化(§6) |

- `beat` は出来事の要約にする。台詞や描写をそのまま写さない。脚本の再現は要らない
- `cast` には、**その場に居る人物だけ**を書く。話題に出るだけの人物は入れない
- 回想は書けない。並べた順が、そのまま「起きた順」として扱われる。
  時系列を入れ替えた作品は、上映順(構成を見たい場合)か、物語の中の時間順(登場人物の知識を正しくしたい場合)の
  どちらで並べるかを先に決める

### 5.1 elapsed(前のシーンからの経過)

1 つ前のシーンから、物語の中でどれだけ時間が経ったか。

```json
"elapsed": { "unit": "day", "count": 3 }
```

| unit | 意味 | count |
|---|---|---|
| `immediate` | 直後。前のシーンからひとつながり | 書かない |
| `same_day` | 同じ日。場面は変わるが、日はまたがない(何時間後かは決めない) | 書かない |
| `hour` | 時間後 | 1 以上の整数 |
| `day` | 日後 | 1 以上の整数 |
| `week` | 週間後 | 1 以上の整数 |
| `month` | か月後 | 1 以上の整数 |
| `year` | 年後 | 1 以上の整数 |

- **最初のシーンには書かない**(前のシーンが無い)
- **分からなければ `elapsed` ごと省略する。** 省略は「決めていない」の意味で、「直後」とは別に扱われる。
  推測で `immediate` にしない
- 何時間後かが分かるときは `hour` にする(「三時間後」「その夜」のように見当が付くとき)。
  同じ日のうちだが時間が分からないときは `same_day` にする
- 「数日後」のように数がはっきりしないときは、もっとも近い数にする(数時間 = 3、数日 = 3、数週間 = 3 など)
- できるだけ書く。省略したシーンを挟むと、それより前の出来事が「いつのことか」分からなくなる。
  特に、**章の最初のシーン**には書く

## 6. events(シーンで起きた変化)

人物の記憶・関係・事実は、イベントを最初のシーンから順に積み上げて作られる。
**イベントが無いと、登場人物は出来事を何も覚えていない**ことになる(プロフィールだけを知っている状態)。
取り込みの質は、ほぼここで決まる。

イベントは 4 種類ある。`type` で種類を選ぶ。

### 6.1 memory(記憶)

その人物が覚えたこと。

```json
{ "type": "memory", "who": "アヤ", "text": "橋脚のひびが去年より二寸広がっているのを、自分の手で測って確かめた。", "importance": 0.8, "emotion": -0.2 }
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `who` | ○ | 覚えた人物 |
| `text` | ○ | 記憶の内容。**その人物の視点**で書く |
| `importance` | | 重要度 0〜1。省略時は 0.5 |
| `emotion` | | そのときの気持ち -1(つらい)〜 1(うれしい)。省略時は 0 |

- **その場に居た人物ごとに書く。** 行動した本人だけでなく、見た・聞いた・気づいた人物にも書く。
  同じ出来事でも、人物ごとに別の記憶になる(見えたものも、感じたことも違う)
- 人から聞いた話は、見たことと区別できる書き方にする。誰から聞いたかを含める
  (例: 「アヤから、北の橋を通行止めにしたと聞かされた」)
- 重要度の目安:

  | 重要度 | 目安 |
  |---|---|
  | 0.8〜1.0 | 人生を変える出来事 |
  | 0.5〜0.7 | 当事者としての重要な体験 |
  | 0.3〜0.5 | 目撃したこと、人から聞いたこと |
  | 0.1〜0.2 | 些細なこと |

- 1 つのシーンで、1 人につき 1〜3 件が目安。細かく分けすぎない

### 6.2 relation(関係の変化)

ある人物の、別の人物への気持ちの変化。**向きがある**(アヤ→ケン と ケン→アヤ は別)。

```json
{ "type": "relation", "who": "ケン", "toward": "アヤ", "change": -0.2, "label": "置いていかれた幼なじみ", "reason": "行き先を聞かされなかった" }
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `who` | ○ | 気持ちを持つ側 |
| `toward` | ○ | 相手 |
| `change` | どちらか | 増減 -1〜1。プラスは好意、マイナスは反感 |
| `value` | どちらか | 絶対値 -1〜1。関係を最初から置くときに使う |
| `label` | | その時点の関係を一言で(例: 「幼なじみ」「ライバル視」「犯人と疑う」) |
| `reason` | | 変化の理由 |

- `change` と `value` は、どちらか一方だけを書く
- 物語の途中の変化は `change` で書く。**小さく刻む**(±0.1〜0.3)。±1.0 に近い値は、人生を変える出来事だけ
- 物語が始まる前からの関係(家族、旧友、宿敵)は、その 2 人が最初に出るシーンに `value` で置く
- 値の目安: 0.6 以上 = 深い信頼・愛情 / 0.3 = 好意的 / 0 = 中立 / -0.3 = 警戒 / -0.6 以下 = 強い憎しみ・恐れ
- `label` は付ける。関係図の矢印に表示される

### 6.3 fact(事実)

人物の状態や、知っていること。

```json
{ "type": "fact", "who": "アヤ", "key": "任務", "value": "北の橋の安全を調べ、通行の可否を判定する" }
{ "type": "fact", "world": true, "key": "季節", "value": "冬の終わり" }
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `who` | 人物の事実なら ○ | 誰の事実か |
| `world` | 世界の事実なら `true` | 誰もが知っている公のこと。このとき `who` は書かない |
| `key` | ○ | 項目名(「目的」「怪我」「持ち物」「知っていること」など) |
| `value` | ○ | 値。文字列・数・true / false |

- 同じ人物の同じ `key` を後のシーンで書くと、**上書き**される(状態の変化を表す)
- **秘密は、知っている人物の事実として書く**(例: `"who": "執事", "key": "知っていること", "value": "真犯人は自分だ"`)。
  `world` に書くと、知らないはずの人物まで知っていることになる
- `world` は、作中の誰もが知っている公のことだけに使う(季節、戦争が始まった、王が死んだ、など)
- **誰がどこに居るかは書かない。** シーンの `cast` と `location` で決まる

### 6.4 retire(退場)

その人物が、このシーンを最後に物語から居なくなる。

```json
{ "type": "retire", "who": "老技師", "reason": "death" }
```

- `reason` は `death`(死亡)か `departure`(去った)。省略時は `departure`
- 退場した人物を、後のシーンの `cast` に入れると誤りになる。一時的にその場を離れるだけなら、退場にしない
  (次のシーンの `cast` から外すだけでよい)

## 7. chapters(章)

幕や部などの大きな区切り。シーンをタイトル(または `key`)で指す。

```json
{ "title": "第二幕 橋", "scenes": ["橋のひび", "通行止め"] }
```

- 1 つの章は、`scenes` の並びの中で**連続する範囲**にする(飛び飛びにしない)
- 1 つのシーンは、1 つの章にだけ入れる。どの章にも入れないシーンがあってもよい
- 同じタイトルのシーンが複数あるときは、シーンに `key` を付けて、`key` で指す

## 8. 検査する

書いたら、必ず検査コマンドを通す。取り込みはせず、誤りだけを表示する。

```
.venv/Scripts/python.exe backend/import_check.py 作品.json
```

- 「誤り:」の行があれば、その内容に従って直し、もう一度検査する。誤りが無くなるまで繰り返す
- 「注意:」の行は、取り込みはできるが、意図どおりか確かめた方がよい点
- 誤りが無ければ「問題ありません。取り込めます。」と出る

取り込みは、アプリの 設定 →「取り込み」から行う。**シーンが 1 つも無いライブラリ**にだけ取り込める。

## 9. 書くときの注意

- **記憶だけで書かない。** 作品の細部や場面の順序は、記憶だけでは間違える。あらすじなどの資料があれば、それを元にする
- **原作の文章を写さない。** 台詞や脚本をそのまま入れず、出来事の要約と、自分の言葉での人物像にする
- 長い作品は、まず `characters` / `places` / `chapters` と、シーンの `title` と `beat` だけを全体に通して書き、
  それから `events` を足していくと、順序の誤りに早く気づける
- 2 時間の映画で、シーンは 40〜60 が目安
