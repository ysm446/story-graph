## 資料庫と分岐の複合検証

`data/production-library-branch-084cf1be` は最初の段階で不合格（147.1秒、4変更、ツールエラー0件）。人物・場所の登録、2シーンの枝作成はできたが、末尾シーンの `location` が登録した小屋のIDではなく `null` だった。本文に小屋を描写するだけで、資料との関連付けを満たしていない。作業メモの最終見直しも場所の未設定を認識したが、その実行では修正しなかった。

後続の資料部分更新・途中指示・未使用資料作成と削除・使用中資料の保持・相談中の編集抑止の6段階は、このテストの初段失敗により未実行。

## 判断

ツール非対応ではなく、基本編集とメモ引継ぎは可能。しかし途中指示3回とも厳密条件に不合格で、保存後の再試行、取り消した依頼の一時的な実行、資料参照の取りこぼしを観測した。現在の制作プロンプトとの組み合わせでは、安定運用を確認できたとはいえない。

Gemmaの改善後テストと同じ条件の途中指示は、Gemma 26B A4B / 12Bでは各3回とも合格した。ただし少数試行の比較であり、モデル全般の能力順位や成功率を示すものではない。次に改善する場合は、保存後の終了判断、取り消された依頼と最新指示の区別、資料登録とシーン参照の整合を優先する。

## 検証範囲

実アプリUIの操作、清書・画像生成、任意の作品に対する品質、31Bとの同条件比較は対象外。検証中に製品コードは変更しない。

専用サーバーは検証後に停止。今回は既存の検証スクリプトをそのまま使用し、製品コード・スクリプトの変更はなく、pytest・buildの再実行はしていない。記録の差分チェックを実施。
