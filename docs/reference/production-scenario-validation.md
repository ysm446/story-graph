## 問題と対応

- 接続図だけでは6章を列挙しながら「4章」と答えた。章数・シーン数をサーバーで集計し、章一覧・所属と一緒に渡すよう修正。
- 枝の入口を正史側の分岐元だけで答えた。分岐元と枝の先頭を別項目にし、両IDで説明する指示を追加。
  試験の質問も「分岐元→枝の先頭」と明示したため、曖昧な表現すべての解消を示す結果ではない。
- 「青い封筒を保管する決意を加える」との依頼に、既存の公開方針と矛盾する「誰にも渡さず」という制限を加えた。
  追記では既存の約束を守り、依頼にない証拠・秘密・制限を足さないよう制作プロンプトを補強。
  再確認では公開と「隠さない」約束を保持したが、封筒を「重要な証拠」とする加筆は残った。
  **プロンプト改善だけで内容の忠実さを保証できる状態ではない。**

追記の再確認: `data/production-scenario-3c8e8e21/`、23.5秒。
`--addition-only` で追記だけを再検証できる。機械的な操作チェックと文章の質の観察は区別する。
最初の不通過記録も `data/production-scenario-0004cd84/` と `data/production-scenario-a12513db/` に残した。

### 発見した不具合と修正

初回は分岐・部分編集・途中指示・資料の削除が成功した一方、指定した場所の説明が空欄だった。
操作結果を確認して説明の取りこぼしを発見し、検証にも指定文字列の一致を追加した。
初回記録 `a85e937f` の `passed: true` は当初の機械的検証だけの結果で、説明欄の要件は満たしていない。
指示と項目説明だけを強めた再試験 `e7ae7ff8` でも再現し、厳密な照合で不合格になった。

稼働中サーバーの `/props` から会話テンプレートを確認すると、`format_parameters` は
`description` / `type` / `properties` / `required` / `nullable` という引数名を除外していた。
そのためJSONスキーマに存在する `description` が、モデルへ渡るツールの引数一覧から消えていた。
場所の説明を保存しなかった原因をモデルの気まぐれだけに帰することはできない。

LLM向け引数を `place_description` に変更し、保存時に既存の `description` へ変換した。
手動編集API・DB・読み取り結果の項目名は維持する。新旧の引数を異なる値で二重指定した場合は拒否する。
各項目の意味と、保存結果の `after` を依頼と照合する指示も補強した。
回帰テストで公開スキーマ、説明の登録・更新・読み取り、他の項目の保持、二重指定を確認した。
