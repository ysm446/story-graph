# goals — プロジェクトの目的と完成形

作成日時: 2026-07-24 22:38
更新日時: 2026-07-24 22:38

## 目的

物語を「ビート(出来事の仕様書)」のDAGとして構築し、各ノードが発行するイベントdiffの畳み込み(fold)によってキャラクター・世界の状態を任意時点で導出できるローカルデスクトップアプリを作る。散文はビートから分離された「レンダリング」として鑑賞モードで生成する。

正式な仕様は [docs/story-graph-spec.md](../story-graph-spec.md)。本ファイルはその要約と価値基準の宣言。

## 設計原則(価値の優先順位)

1. **ビートが正史、散文はレンダー結果。** 状態抽出・編集・分岐はすべてビート層で行う。
2. **状態は保存せず、常に導出。** キャラ状態のマスターデータは存在しない。ルートからのイベント畳み込みが唯一の真実。
3. **関係はスパース。** イベントが発行されたペアにしかエッジは存在しない。
4. **レンダリングは状態を変更しない。** 散文化は読み取り専用の一方向変換。
5. **LLM由来の変更も手動修正も、同じイベントとして記録する。**

## 完成形(Phase 6 完了時の姿)

- **構造モード**: React Flow キャンバス上で正史タイムライン+分岐DAGを編集。ビート生成/ブランチ生成/手動記入。インスペクタで任意時点のキャラ状態(facts / relationships / memories)を閲覧・手動イベントで修正。
- **鑑賞モード**: 正史パスをスタイルプリセット+POV指定でシーケンシャルに散文化。部分再レンダー、ビート昇格(散文→正史への唯一の還流)。
- **関係グラフ**: 時間スクラブ付き有向グラフ。エッジクリックで理由イベント履歴をドリルダウン。
- **相談チャット**: 状態の読み取り専用エージェント。アンカーノードまでのスコープ制御、提案カード→draftブランチ挿入。
- すべてローカル(llama.cpp + Gemma4-31B、SQLite)で完結。マルチユーザー・クラウド同期はしない。

## 非目標

- 画像・動画生成、シーンカードの視覚演出(story-flow の領分)
- マルチユーザー / クラウド同期
- 実時間ベースの記憶減衰(物語内順序のみを使う)
- ノードトポロジーによる自由なコンテキスト配線(lm-graph の領分)
