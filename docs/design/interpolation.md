# 間のシーン生成(補間)

作成日時: 2026-08-11 12:42
更新日時: 2026-08-11 12:42

2026-08-11 ユーザー発案。「▶ 次のシーンを生成」を、選択ノードに後続シーンがあるときは
**前後の両方を見た補間生成**(間に起こったであろう出来事の推測)にする。

## 1. 背景と問題

- 「▶ 次のシーンを生成」は選択ノードを見ず、常に正史の末尾(章内ビューでは章の
  出口の手前)に足す仕様だった。
- 一方で `/generate/beat` の `after_id`(直後への割り込み)は実装済みで、章の中の
  生成はすでに割り込みになっている。しかし**生成プロンプトは上流(直近 3 ビート)しか
  知らない**ため、割り込みで作られたシーンは後続と平気で矛盾しうる。
- 2 つのシーンの間が飛びすぎているとき「橋渡しのシーン」を足すのはよくある操作だが、
  これまでは手書きするしかなかった。

## 2. 方針

- **選択ノードに「次のシーン」があれば補間、無ければ従来どおり末尾に追加。**
- 補間の生成プロンプトに「## 次のシーン(この後に起こること)」を注入し、
  「先取りしない・矛盾しない・終わりの状況が次のシーンの冒頭につながる」を制約にする。
- 挿入自体は既存の `insert_node_after`(スプライス + 下流の再 fold + 清書 stale)に
  任せる。**新しい書き込み経路は作らない。**

## 3. 「次のシーン」の決め方(`generation.next_scene_after`)

挿入先の選び方(`insert_node_after` の chain_edge)と同じ規則で子を選び、
マーカーを読み飛ばして最初の**シーン**を採る:

1. canon の子がいればそれ。
2. 無ければ、同じ章の出口(chapter_out)。島・正史でない章の中はどのエッジも
   is_canon=0 のため(insert_node_after と同じ理由)。
3. それも無ければ、子が 1 つだけのときその子(島の一本道)。分岐していて
   決められないときは None(= 従来の末尾追加)。
4. 採った子がマーカーなら、そのマーカーから同じ規則で先へ辿る。
   - 章の入口 / 出口 → 読み飛ばして次へ(章末で押した場合、挿入は出口の手前・
     文脈の次シーンは**次章の先頭**になる。章の境界規則と整合)
   - 結末 → None(次のシーンは無い)

章の中への従来の追加(after_id = 章の route 末尾)でも同じ経路を通るので、
**後ろに次章があるなら自動的にその先頭が文脈に入る**(矛盾防止として常に有益)。

## 4. プロンプト

- `_build_messages` に `next_scene` を追加。「## 直近のビート」と「## 指示」の間に
  次のシーンの title / cast / location / beat を出す。
- 既定の指示(指示欄が空のとき):「直前のビートと次のシーンの間に起こった出来事を
  1 つ設計してください」。
- ユーザー指示があってもなくても、補間時は制約を後置する:
  先取りしない / 矛盾しない / 終わりの状況(場所・居合わせる顔ぶれ)が次のシーンの
  冒頭へ自然につながる。
- 意味的な「先取り」まではルール検証で弾けない。draft として出して作者が直す前提
  (ビートは仕様書なので直すのが安い)。主に使うのは 31B なので追従は期待できる。

## 5. UI(構造モード)

- 生成パネルのボタンは選択に応じて文言を切り替える(校正ボタンと同じ作法):
  - 選択なし / 後続なし → 「▶ 次のシーンを生成」(従来)
  - 後続あり → 「**▶ 間のシーンを生成**」+ title に前後のシーン名
- このとき `after_id = 選択ノード` を渡す。それ以外は従来の章末ロジック
  (`focusedGroup.route.at(-1) ?? in_id`)のまま。
- 単一シーンの右クリックにも「⧉ 間のシーンを生成」を出す(後続があるときだけ)。
  どの間に挟むかが画面上で明確になる。
- フロント側の後続判定はラベル表示用の近似(canon の子 → 同章の出口 → 唯一の子、
  マーカーは読み飛ばし)。実際の挿入位置と文脈はサーバー側が決める。

## 6. やらないこと

- 分岐(⑂)の意味は変えない(分岐は「別の未来」であって補間ではない)。
- 複数の子で分岐しているノードでの補間(どの間か決められない。従来の末尾追加に
  フォールバック)。
- エッジの右クリックメニュー(エッジ操作は現状クリック + Delete とダブルクリック
  だけなので、新しい操作系を増やさない。ノードの右クリックで足りる)。
