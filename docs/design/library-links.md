# 資料庫の拡張 — 世界観・組織・資料間リンク

作成日時: 2026-10-11 12:35
更新日時: 2026-10-30 17:28

## 2026-10-12 の採用方針と実装

まずリンクを持たない「設定資料集」を資料庫に設置した。以下のリンク・被リンク・グラフ案は過去の検討記録として残し、今回の実装範囲には含めない。

- 資料庫の階層メニューに「設定資料」を追加。タイトル、自由入力の分類、Markdown本文、資料の扱い（確定設定・構想・参考資料）、適用範囲・時点、AIへの参照方法を編集する。新規資料は「構想」「必要に応じて検索」。
- 一覧の絞り込み、本文プレビュー、未保存バッジ、元に戻す、削除確認を備える。資料・種類を切り替えても下書きを保持し、未保存中は制作実行を防ぐ。
- 本文は `setting_documents` を正本とする。更新時に revision を照合して競合を拒否する。本文は最大10万文字で保存し、検索索引は最大1200文字の断片に分割する。
- `setting_document_chunks` の埋め込みとFTS5索引を保存・削除に連動して更新する。既存のRuriを使い、全文検索と意味検索の順位を統合する。モデル未ロード時・失敗時は全文検索を使い、ロード後の検索で未作成・モデル変更済みの埋め込みを再生成する。ベクトルはSQLiteのBLOBに保存し、検索時に内積を計算する。
- 相談・制作チャットに読み取り専用の `search_setting_documents` / `read_setting_document` を追加。「常に参照」は毎回全文をコンテキストへ含め、「参照しない」は検索・直接取得から除外する。過去にチャットへ渡した内容を履歴から消す機能ではない。
- 設定資料は人物本人の会話・会話室へ渡さない。資料の扱いと適用範囲を作者向けプロンプトで説明し、構想・参考資料を確定した事実と混同しないよう指示する。適用範囲・時点は自由記述であり、アンカーによる自動制限はしない。
- 制作実行に限り `create_setting_document` / `update_setting_document` で作成・編集できる。更新前に全文とrevisionを読み、指定した項目だけ更新する。省略項目は維持し、同名作成・古い版の上書き・「参照しない」資料の編集を拒否する。新規は構想・検索を既定にし、確定設定や参照方法の変更は作者の明示指示に従うようプロンプトで指示する。
- 編集開始・作成更新の確定後に対象の設定資料へ画面を追従させる。途中指示による中断、未保存資料の制作ガード、制作前スナップショット、変更履歴は既存の制作処理を使う。設定資料の削除ツール、シーンの状態への自動反映、時点別・分岐別管理は未実装。既存のキャラクター・場所を置き換えない。

## 位置付け

次に検討するテーマとして、2026-10-11 の会話をまとめた設計メモ。
世界観・組織の資料を追加し、Obsidianのように資料同士をリンクで辿れる構造を目指す。
この文書は検討の出発点であり、実装済みの仕様ではない。具体的な保存形式・画面構成・実装範囲は未確定。

## 背景と方向性

現在のキャラクター・場所に加え、魔法の仕組み、文化、社会制度、国家や組織なども資料として扱いたい。
資料庫を構造画面のようにノード化する案から、各資料の本文中のリンクによってネットワークが生まれる案へ議論が進んだ。

目指すのは、資料を書きながら関連付けられ、一覧・検索・リンク・グラフのどこからでも目的の資料へ到達できること。
資料のグラフは参照関係を表す。シーンの順序や分岐を表すDAG、時点ごとの人物関係グラフとは役割が異なる。
リンクをLLMの自由なコンテキスト配線として扱うものではなく、[プロジェクトの非目標](../plan/goals.md)は維持する。

## 資料の種類

| 種類 | 内容の例 | 検討する扱い |
|---|---|---|
| キャラクター | プロフィール、外見、口調 | 既存の専用項目・画像・IDを活かす |
| 場所 | 説明、雰囲気、拠点 | 既存の専用項目・画像・IDを活かす |
| 世界観 | 魔法・技術の仕組み、文化、宗教、社会制度、歴史 | 「魔法の制約」「王国の身分制度」など項目ごとに登録する案 |
| 組織・勢力 | 国家、企業、ギルド、家族などの目的・方針・構成 | 新しく項目を決める案 |

以前の `factions`(名前・説明・所属キャラだけ)は、作る画面も使い道も無いまま 2026-10-30 に廃止した。
組織を扱うときは、その時点で必要な項目から決め直す。
キャラクターや場所を、専用項目のない汎用メモへ一律に置き換えることは想定しない。

## リンクと被リンク

本文中に `[[資料名]]` と書き、別の資料へ移動できる方式を候補とする。
この記法や保存形式は未確定であり、Obsidianのファイル形式や同期機能との互換性を約束するものではない。

例: 「王立魔術院」の説明

> [[王都]]に本部を置く研究機関。[[魔法の制約]]を研究している。[[リナ]]との関わりは人物資料と各シーンを参照。

この例では組織から場所・世界観・人物へ移動できる。
リンク先には「この資料に言及している資料」を被リンクとして表示する。
リンクはまず「関連資料への参照」を意味し、所属・敵対・居場所などの状態を自動的に確定しない。

実装時には次を決める。

- 同名資料の区別と候補選択。種類をまたいだ同名も扱う。
- 改名しても参照が切れない識別方法。表示名と安定したIDを分離する案を検討する。
- 未作成のリンク先、削除済み資料、別名の扱い。誤った資料へ黙って結び直さない。
- どの文章欄をリンク対象にするか。コード例やエスケープされた記法をどう扱うか。
- 被リンク・グラフ用の索引を本文と同期する方法。二重管理で内容が食い違わないようにする。

## 時間軸との役割分担

基本方針は「資料庫は設定の事典、シーンは変化の記録」。
資料庫の関連リンクに、現在の所属や物語内の有効期間を背負わせない。

| 扱う情報 | 責務 |
|---|---|
| 魔術院とは何か、魔法にはどのような制約があるか | 資料庫の設定・説明 |
| リナが加入した、脱退した、魔術院が崩壊した | シーンで起きる出来事 |
| 選んだシーンの時点で誰が所属しているか | 対応するイベントとfoldで導出する状態 |
| リナと魔術院に何らかの関わりがある | 資料間の参照リンク |

人物から組織へのリンクが残っていても、その人物が現在も所属しているとは限らない。
資料本文の「所属している」という文章も、全時点に適用できる事実としては扱わない。
開始時点の設定、過去の説明、将来の構想などが混ざる場合の記述・表示方法は検討が必要。

組織の所属・存続や世界観の変化を時点ごとに扱うためのイベント・foldの対応範囲は、実装前に確認する。
未対応の状態を資料リンクから推測して埋めず、必要なら別の拡張として設計する。
資料庫自体の時点別履歴や分岐別バージョン管理は、初期段階に含める前提にしない。

## 画面の構成案

- 一覧・検索: 種類で絞り込み、資料を探す。グラフを使わなくても編集できる。
- 資料の詳細: 既存の専用項目に加え、説明中のリンクと被リンクを扱う。
- グラフ表示: 各資料をノード、参照を線として表示する。選択すると資料の詳細を開く。

グラフは本文の参照関係から導出する案を優先し、線だけを別に手動管理する必要を増やさない。
全体表示と選択資料の周辺表示、種類による絞り込み、配置の保存は後続の検討事項。
見た目の具体値は [スタイルガイド](style-guide.md) に従う。

## AIからの利用

世界観・組織を相談・制作チャットから検索・参照できるようにする案。
リンク先を無制限に展開せず、必要な資料を出典とともに参照できる形を検討する。
AIにも「資料の関連リンク」と「対象時点の状態」を分けて渡す。
資料には未来の構想や秘密が含まれる可能性があるため、リンクを辿るだけで既存のアンカー範囲や知識境界を越えない設計が必要。
制作による世界観・組織の編集対応は、読み取り対応と分けて範囲を決める。

## 実装順序の案

1. 既存の資料モデル・検索・チャット参照経路を確認し、世界観と組織の最小項目を決める。
2. 世界観・組織の登録・編集・一覧と、相談・制作からの参照を揃える。
3. 資料間リンク・リンク先への移動・被リンクを追加する。
4. 同じリンク情報を用いてグラフ表示を追加する。

次の検討では、まず段階1〜2の範囲と、改名・同名に耐えるリンクの識別方法を決める。
具体的な日程、DB変更、画面レイアウトは未確定。

## 関連する別テーマ

制作チャットの「作業対象を追う」で資料の変更先も表示したい、という要望がある。
現在チャットは構造画面内にあるため、資料庫へ移るとチャットが見えなくなる点が課題。
チャットを共通のサイドパネルにする案が出ているが、まだ決定していない。
資料リンク・グラフ表示の追加とは独立に検討できる。

## 実装時に確認すること

- 既存のキャラクター・場所・画像と、バックアップからの復元を維持できる。
- 改名・同名・削除・未解決リンクで誤った参照が生じない。
- 本文の編集に被リンクとグラフが追従する。
- 資料リンクの追加・削除だけでは、シーン・正史・fold結果が変化しない。
- 加入前・所属中・脱退後で同じ資料リンクがあっても、AIが現在の所属と混同しない。
- 長文や多数の資料でも、一覧・検索から目的の資料へ到達できる。
