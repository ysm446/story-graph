# イベントの古さの印

作成日時: 2026-11-10 20:20
更新日時: 2026-11-14 23:45

シーンの本文を書き替えたあと、イベントを取り直していないシーンに印を付ける仕組みの設計。
「時間が余ったときにまとめて更新する」機能(§7)の土台になる。

**状態(2026-11-10): 印の仕組み(§2〜§6)を実装済み。「まとめて更新」(§7)は [bulk-update.md](bulk-update.md) に設計した(未実装)。**

## 1. 目的

- 清書には「要更新」、章のまとめには「まとめ要更新」の印があるが、**イベントには無い**。
  本文を直してもイベントは元のままで、どのシーンが食い違っているかは作者が覚えているしかない。
- イベントは正史の状態(記憶・関係・事実)の元なので、食い違ったままだと、その先の生成・清書・
  キャラ会話が古い状態を前提にする。
- 印があれば、作者は直すべきシーンが分かり、「まとめて更新」は印の付いたシーンだけを拾える。

## 2. 方式: 本文の指紋を比べる

イベントを書いたときの本文の指紋(ハッシュ)をシーンに保存し、いまの本文の指紋と比べる。
**「古い」という印そのものは保存しない**(設計原則 2 と同じ考え方。`state_cache` の `input_hash` と同じ型)。

採らなかった案: **本文を書き替えたときにフラグを立てる**。
- 本文が変わる経路(手での編集、校正、制作チャット、取り込み、貼り付け)すべてに「立てる」処理が要り、
  1 か所漏れると印が付かない。指紋なら、どの経路で変わっても比べれば分かる。
- 書き替えてから元に戻しても、フラグは立ったままになる。指紋は一致するので古い扱いにならない。

### 指紋に入れるもの

イベント抽出のプロンプト(`generation.extract_events`)に入る、**そのシーン自身の入力**。

| 入れる | 理由 |
|---|---|
| `beat`(本文) | 抽出の主な材料 |
| `cast`(登場人物) | プロンプトに出る。誰の記憶・関係を作るかに効く |
| `location`(場所) | プロンプトに出る。そのシーンに設定された値だけ(前から引き継いだ場所は入れない) |

入れないもの:
- **タイトル、感情の核、経過、目標の字数、挿絵**: 抽出のプロンプトに入らない。
- **前のシーンまでの状態、キャラクター一覧**: 抽出のプロンプトには入るが、これを入れると上流を 1 つ直すたびに
  下流がすべて「古い」になる。印の意味は「**このシーンの本文とイベントが食い違っている**」に絞り、下流へは広げない
  (上流の変更が下流に及ぼす影響は、いまも清書の「要更新」が受け持っている)。

指紋の作り方: 本文は前後の空白を落とし、改行を `\n` に揃える。登場人物は並べ替える(順番だけの変更で印を付けない)。
これらを JSON にして SHA-1 を取る(`db.events_fingerprint`)。

## 3. 状態

シーンに列を 1 つ足す: `nodes.events_basis TEXT`(イベントを書いたときの指紋。NULL = まだ一度も書いていない)。

| 状態 | 条件 | 画面の言葉 |
|---|---|---|
| 最新 | `events_basis` がいまの指紋と同じ | (印なし) |
| 古い | `events_basis` があり、いまの指紋と違う | イベント要更新 |
| 未作成 | `events_basis` が NULL で、本文が空でない | イベント未作成 |

- 本文が空のシーンは、どちらの印も付けない(抽出するものが無い)。
- はじまり / 結末のマーカーには付けない。
- API は、シーンを返すとき(`get_node` / `graph`)に計算した `events_status`(`"stale"` / `"missing"` / `null`)を添える。
  `events_basis` そのものは画面に渡さない。

## 4. いつ指紋を覚えるか

**イベントを書いたとき**。書き込みは `Store.replace_events` に集約されているので、そこで覚える。

| 経路 | 覚える | 理由 |
|---|---|---|
| イベントの抽出(作り直す) | ○ | いまの本文から作った |
| イベントの手での編集(保存) | ○ | 作者が本文を見たうえで整えた。取り直す必要はない |
| 生成でシーンとイベントを一緒に作る | ○ | 同じ本文から作った |
| 制作チャットの後追い(`reextract_stale`) | ○ | 抜き出しの前後で本文が変わっていないことを確かめてから書く |
| 取り込み(JSON)、貼り付け | ○ | 本文とイベントが組で入ってくる |
| **「このままでよい」**(§5) | ○ | イベントは書き替えず、指紋だけ覚え直す |
| 登場イベントの掃除など、保守のための書き替え | × | 本文と突き合わせていない。`replace_events(..., record_basis=False)` |

イベントが 0 件で保存された場合も覚える(「抽出したが何も無かった」「作者が空にした」は最新)。

### 知っておくこと

- **誤字を直しただけでも印が付く。** 内容が変わったかどうかは機械には分からない。「このままでよい」で消す。
- **貼り付けたシーンは最新になる。** 元のシーンが古かった場合も引き継がない(貼り付けはイベントを書く操作なので)。
  困るようなら、指紋も一緒に写すようにする。
- **制作チャットが本文だけを書き替えた場合は印が付く。** 正しい動き(イベントを直していないので)。
  2026-11-14 から、制作の作業は**いつも本文だけを確定し**、作業の終わりに印の付いたシーンを自動で作り直す
  ([production-chat.md「イベントの後追い」](production-chat.md))。印は「後追いがまだ・できなかった」の目印も兼ねる。

## 5. 画面

### シーンのカード

章カードの「まとめ要更新」と同じバッジ(`rounded px-1.5 py-px text-[10px]`、下地 `rgba(239,68,68,0.12)`、文字 `--danger-text`)。

- 古い: `イベント要更新`。ツールチップ「本文を書き替えたあと、イベントを作り直していません」
- 未作成: `イベント未作成`。ツールチップ「本文はありますが、イベントをまだ作っていません」

### 詳細欄のイベントの見出し

見出しの行(Events の件数と「+ 手動イベント」「イベント抽出(LLM)」)のすぐ下に、印のあるときだけ 1 行足す。
左に同じバッジ、右に印を消すボタン。

- **直すとき**: 見出しの行に元からある「イベント抽出(LLM)」を使う(手で足したイベントは残る)。
  同じ操作のボタンを 2 つ置かないよう、印の行には抽出のボタンを足さない。
- **このままでよい**: 二次ボタン。ツールチップ「イベントは変えず、いまの本文に合っているものとして印を消します」。
  `POST /nodes/{id}/events/confirm`。物語の状態は変わらないので、スナップショットも清書の要更新も起きず、
  実行キューにも積まない。未作成のときの文言は「イベントなしでよい」。

文言は `eventsStatus.ts` にまとめ、カードと詳細欄で同じ言葉を使う。

### 一覧で拾う

構造モードの右クリックメニューに「イベントが古いシーンを選択」を足すかは、§7 を作るときに決める
(「まとめて更新」が拾うなら、手で選ぶ必要は薄い)。

## 6. 既存のライブラリ(移行)

列を足したとき、過去にさかのぼって古さを判定する材料は無い。

- **イベントが 1 件でもあるシーン**: いまの指紋を入れる(= 最新として扱う)。
- **イベントが 1 件も無いシーン**: NULL のままにする(= 本文があれば「未作成」)。
  抽出して 0 件だったシーンも「未作成」に見えるが、「イベントなしでよい」で消せる。

移行は `db.py` のマイグレーションで 1 回だけ行う(`SCHEMA_VERSION` 5)。指紋の計算は Python 側で行うので、
SQL だけでは書けない。指紋を作る関数 `events_fingerprint` は `db.py` に置き、マイグレーションと `store.py` の両方から呼ぶ
(`store.py` は `db.py` を読み込む側なので、逆向きには置けない)。

## 7. この先: まとめて更新

設計は [bulk-update.md](bulk-update.md) に移した。以下は設計前の論点の控え。

2026-11-10 のユーザーの要望: 出かける前や寝る前に実行して、イベントや清書の更新を順に続けてほしい。

- 対象を自動で拾う: イベントが古い・未作成のシーン、要更新のまとめ、要更新・未清書の清書。
- 順番: イベント(上流から)→ 章のまとめ → 清書。
- イベントの作り直しは正史を変えるので、既定は清書とまとめだけにし、イベントは選んだときだけにする。
  始める前にスナップショットを取り、手で足したイベントは残す。
- 1 件失敗しても止めず、最後に結果(何件更新、何件失敗)を残す。
- 自分で押して始める。操作が無いときに自動で始める形は、最初は作らない。

## 8. 検証

`backend/tests/test_event_staleness.py`。

- 抽出・手での保存・シーンとイベントの同時作成のあとは最新。
- 本文・登場人物・場所を変えると古い。タイトルや経過を変えても変わらない。
- 本文を元に戻すと最新に戻る。前後の空白、改行コード、登場人物の並びだけの違いでは古くならない。
- イベントを一度も書いていないシーンは、本文があれば未作成、空なら印なし。
- 「このままでよい」で印が消え、イベント・清書の要更新・状態は変わらない。
- 上流の本文を変えても、下流のシーンは古くならない。
- 登場イベントの掃除では指紋が変わらない。
- 移行: イベントのあるシーンは最新、無いシーンは未作成。2 回走らせても変わらない。
- マーカーには印が付かない。

画面は隔離 Electron(`scripts/check-workspace-ui.cjs --eventstale`)で、未作成 → 印を消す → 本文を書き替えて要更新 →
印を消す → イベントを保存して消える、の流れをカードと詳細欄の両方で見る。
