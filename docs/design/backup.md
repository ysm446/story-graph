# 外部バックアップ(zip 書き出し)設計

作成日時: 2026-08-05 20:25
更新日時: 2026-08-05 21:00

## 目的

ライブラリを **フォルダの外へ丸ごと持ち出せる** ようにする。

既存の[スナップショット](snapshots.md)は「危険な操作をやり直す」ためのもので、
`<ライブラリ>/snapshots/` に置かれる。つまり **ライブラリのフォルダごと消えた /
ディスクが壊れた / 間違ってフォルダを消した** という事故には無力で、守備範囲が違う。

| | スナップショット | 外部バックアップ(本書) |
|---|---|---|
| 守るもの | 操作ミス(削除・正史切替・イベント作り直し) | フォルダ消失・ディスク障害・PC 乗り換え |
| 置き場所 | ライブラリの中(`snapshots/`) | 既定はライブラリの外(ドキュメント配下)。中(`backups/`)も選べる |
| 中身 | `story-graph.db` のみ | `story-graph.db` + `assets/`(挿絵・立ち絵) |
| 契機 | 危険な操作の直前(自動)+ 手動 | 日次(自動)+ 手動 |
| 戻し方 | その場で時点に戻す | **新しいライブラリとして展開して開く** |

## zip の中身

```
<name>-20260805-202500.zip
  backup.json         … マニフェスト(format / created_at / library_name / kind / 件数)
  story-graph.db      … VACUUM INTO の整合コピー(deflate 圧縮)
  assets/images/...   … 挿絵・立ち絵・動画(無圧縮格納 = store)
  snapshots/...       … 既定では含めない(手動書き出し時にチェックで含められる)
```

- **DB は `VACUUM INTO`** で取る。WAL の途中でも単一ファイルの整合コピーが出る
  (スナップショットと同じ作法)
- **画像・動画は無圧縮格納**(`ZIP_STORED`)。既に圧縮済みの形式なので、
  deflate しても縮まないうえ書き出しが遅くなる。テキスト主体の DB とマニフェストだけ deflate
- **`snapshots/` は既定で含めない**。zip 自体が時点バックアップなので、
  30 世代ぶんの DB を毎回持ち出すと数十倍のサイズになる

## 書き出しの実装(イベントループを塞がない分割)

FastAPI のハンドラは全て `async def` でイベントループ上を直列実行する前提
(SQLite の書き込み競合回避)。zip 書き出しは assets が大きいと数秒かかるため、
**SQLite に触る部分だけをループ上で行い、ファイルのコピーはスレッドへ逃がす**。

1. `prepare_db(store)` — ループ上。`VACUUM INTO` で一時フォルダに DB のコピーを作る
2. `write_zip(db_copy, root, dest, ...)` — `asyncio.to_thread`。SQLite には触らず、
   一時 DB と `assets/` を読んで zip に書く。書き込みは `<dest>.part` へ行い、
   最後に `os.replace` で置き換える(**途中で失敗した zip を残さない**)
3. 一時フォルダを消す

## 自動バックアップ

- **既定はオフ**(2026-08-05 ユーザー判断)。ライブラリの外へファイルを作る機能なので、
  「どこに何が置かれるか」を作者が決めてから始める。設定画面でオンにすると動き出す。
  オフでも「今すぐバックアップ」と手動の zip 書き出しは使える
- 保存先は 2 通りから選ぶ(2026-08-05 ユーザー要望)。
  - **外のフォルダ**(既定): `<ドキュメント>/story-graph-backups/<ライブラリのフォルダ名>/`。
    任意のフォルダに変更可(別ドライブ・クラウド同期フォルダを選べば事故に強い)
  - **ライブラリの中**: `<ライブラリ>/backups/`。フォルダを丸ごと運べばバックアップも
    付いてくる / ライブラリを切り替えても迷子にならない代わりに、**フォルダごと失う事故には
    効かない**。zip には画像・動画が入るのでライブラリのサイズはその分ふくらむ
  - 中に置いても**再帰は起きない**。zip に入れるのは `story-graph.db` と `assets/`
    (+任意で `snapshots/`)だけで、`backups/` は集めないため
  - 中に置く設定はパスではなく真偽値(`backup_inside`)で持ち、実際のパスは root から導く。
    外のパス(`backup_dir`)は中に置いている間も保持するので、戻したときに選び直さなくてよい。
    フォルダを選ぶ操作は「外に置く」の意思表示として扱い、自動でオフにする
- ファイル名: `<ライブラリ名>-auto-<YYYYMMDD-HHMMSS>.zip`
  (手動書き出しは `-auto-` が入らない。**ローテーションが手動書き出しを消さない**ため)
- 世代: 直近 N 個(既定 5)。`<ライブラリ名>-auto-*.zip` だけを対象に古いものから削除
- 間隔: 24 時間。最後の実行時刻はライブラリの settings に持つ(`backup_last_at`)
- **中身が無いライブラリ(シーン 0 件)は対象外**。動作確認用の空フォルダを
  開いただけでバックアップが増えない

### なぜ「アプリ終了時」ではなく「日次(起動時チェック)」か

当初案は「アプリ終了時 or 日次」だったが、**起動時の日次チェック**に寄せた。

- 終了時にやると `before-quit` で数秒待たされる(assets が大きいほど)。
  待てずにタスクマネージャで落とされると **バックアップが取れない上に終了も遅い**
- アプリを閉じている間はデータが変わらないので、**起動時のバックアップの中身は
  「前回終了時点」と同じ**。取り逃すのは「今のセッションでの編集」だけで、それも次回起動時に入る
- 起動直後に走らせると、**再利用 sidecar のライブラリ同期**(レンダラが
  `/library/switch` を投げる)より先に走って別のライブラリを撮りかねないので、
  15 秒待ってから実行する。ライブラリ切替の直後にもチェックする

自動保存の失敗は**アプリの動作を止めない**(ログのみ)。保存先が外付けドライブで
未接続、といった状況が普通に起こるため。

## 復元

**既存のライブラリを上書きしない。** zip は「新しいライブラリとして」展開して開く。

1. zip を選ぶ → マニフェストを読んで内容(日時・シーン数の代わりにファイル構成)を確認
2. 展開先のフォルダを選ぶ(空でなければならない。`story-graph.db` があると 400)
3. 展開(zip slip 対策として、絶対パス・`..` を含むエントリは拒否)
4. `library:switch`(Electron の app.json)+ `/library/switch`(バックエンド)→ `location.reload()`

「今のライブラリに戻す」形にしないのは、**復元の失敗が現物を壊す**からで、
そこはスナップショットの担当。外部バックアップは「別の場所に取り出す」に徹する。

## API

- `POST /backup/export` `{path, include_snapshots?}` — 手動書き出し
- `GET /backup/config` — 自動バックアップの設定 + 保存先にある zip の一覧
- `PUT /backup/config` `{enabled?, dir?, keep?}` — 設定変更
- `POST /backup/auto` `{force?}` — 日次チェック(force で即実行)
- `POST /backup/inspect` `{path}` — zip のマニフェストを読む(復元の確認用)
- `POST /backup/restore` `{path, dest_root}` — 新しいライブラリとして展開
- ライブラリ未設定(テストの `:memory:` 等)では書き出し系は 400

保存先・zip のパスはネイティブのダイアログ(Electron main)で選び、
**パス文字列をバックエンドに渡す**。バックエンドは同じ PC にいるので、
ファイル本体を HTTP に流す必要はない。

## UI

設定画面の「バックアップ」セクションを 2 枚のカードに分ける。

1. **外部バックアップ(zip)** — 本書。書き出しボタン / 自動バックアップの
   オン・オフ・保存先・世代数 / 保存先にある zip の一覧 / zip から復元
2. **スナップショット** — 従来どおり

## 制限・既知の注意

- 復元は**新しいフォルダへの展開**なので、元のライブラリと二重に持つことになる。
  不要になったら手で消す
- 設定は DB の中(settings)にあるので、**復元したライブラリは元のライブラリの保存先設定を
  引き継ぐ**。フォルダ名が同じだと自動バックアップのファイル名も同じ形になるため、
  元と復元先を並行して使うなら保存先を変える
- SSE ストリーム(清書・再抽出)の進行中に書き出すと、DB のコピー時点と
  assets の読み取り時点がわずかにずれる。挿絵は追加のみなので実害は
  「まだ参照の無いファイルが入る」程度
- zip は 4GB 超で ZIP64 になる(Python の `zipfile` が自動で切り替える)
