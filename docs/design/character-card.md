# キャラクターカードの書き出し

作成日時: 2026-11-10 18:26
更新日時: 2026-11-10 19:33

ある時点のキャラクターを zip 1 つに書き出し、ほかのアプリで使えるようにする機能の設計。
ファイルの形式は [docs/reference/character-card-format.md](../reference/character-card-format.md)(以下「形式」)が正本で、
本書は **story-graph がそれをどう作るか** を扱う。

**状態(2026-11-10): 段階 1 を実装済み。段階 2 は未設計。**

## 1. 目的と位置づけ

- story-graph で育てたキャラクターと、別のアプリで話したい(最初の相手は音声会話アプリ
  story-graph-voice-chat)。story-graph の中に音声会話を作ると目的(goals.md)から外れるので、
  会話は別アプリに任せ、story-graph は**キャラクターを渡すところまで**を受け持つ。
- 渡すのは「任意の時点の状態を導出できる」という story-graph の強みをそのまま活かした、
  **時点つきの写し**。「3 章の時点の彼女」と「結末後の彼女」を別のカードとして書き出せる。
- 設計原則 4(レンダリングは状態を変更しない)と同じ扱い。書き出しは読み取り専用の一方向変換で、
  清書や朗読と同じく、ビートにも状態にも何も書かない。
- 読む側のアプリからは何も戻ってこない。カードを story-graph に読み込む機能は作らない。

## 2. 段階

| 段階 | 内容 | LLM |
|---|---|---|
| 1 | 設定・状況・関係・記憶・画像・声を、そのまま写して zip にする | 使わない |
| 2 | `summary`(いまの本人のまとめ)と `examples`(口調の手本の台詞)を作って足す | 使う |

段階 1 だけで読む側は話せる。要約が要るか、どのくらいの長さが良いかは実際に話してみないと分からないので、
段階 2 は段階 1 のカードを使ってみてから設計する(§8)。本書の §3〜§7 は段階 1。

## 3. 何を写すか

材料はキャラ会話のシステムプロンプト(`chat_agent.build_character_system`)と同じ。
**文字で話した相手と、カードで渡す相手を食い違わせない**ため、言葉の選び方と知識の境界は
キャラ会話の関数をそのまま使い、写しを作らない。

道(どのシーンまでを畳み込むか)は、キャラ会話でアンカーを指定したときと同じく
`store.path_to(anchor)` からマーカー(はじまり / 結末)を除いたもの。状態は道の末尾の `store.get_state`。

| カードの項目 | 元 | 作り方 |
|---|---|---|
| `language` | — | `"ja"` 固定 |
| `source.app` / `app_version` | `package.json` の `version` | メインプロセスが環境変数でバックエンドへ渡す。無ければ省く |
| `source.character_id` / `node_id` | キャラクターの ID / 道の末尾のシーンの ID | |
| `source.library` | ライブラリのフォルダ名 | ライブラリの名前はフォルダ名そのもの(overview.md §2) |
| `source.label` | 作者が確認ダイアログで決める | 既定は `「<シーンのタイトル>」の直後`。無題なら `(無題)の直後` |
| `source.exported_at` | 現在時刻 | `YYYY-MM-DD HH:MM` |
| `name` / `reading` / `profile` / `appearance` | `characters` の同名の列 | そのまま |
| `speech` | `characters.voice`(口調) | そのまま。列の名前は `voice` だが、カードの `voice` は声(音)なので名前を変える |
| `situation` | 状態の本人の facts | `キー: 値` の形で 1 件ずつ。並びは facts の順 |
| `world` | 状態の world facts | 同上。world facts は「誰もが知っている公のこと」という規約なので渡してよい |
| `relationships` | 状態の本人の relationships | 下記 |
| `memories` | 状態の本人の memories | 下記 |
| `images` | `characters.portrait_path` → `avatar`、`ref_image_path` → `reference` | `assets/images/` から同梱 |
| `voice` | `characters.voice_profile_id` の `voice_profiles` | 下記 |

入れないもの: 設定資料(作者向けで、本人に渡さない決まり)、他のキャラクターの `profile`(内面)、
道より先の出来事、色・座標などの画面用の値、画像の生成プロンプト、切り抜き前の元画像。

### relationships

- `name`: 相手の名前。`appearance`: `_appearance_hint`(外見の先頭 60 字)。
- `feeling`: `_describe_score` の言葉に、ラベルがあれば「」で添える(例: `深い信頼・愛情「家族」`)。
  **数値は入れない**(形式 §3)。キャラ会話では「強さ +0.72」も渡しているが、これは story-graph の
  内部の尺度で、読む側には意味が伝わらない。
- 並び: 関係値の絶対値が大きい順(好悪どちらでも、強い気持ちほど本人にとって重要)。
- 相手のキャラクターが削除済みのものは省く(キャラ会話は ID をそのまま出しているが、カードでは意味を持たない)。

### memories

- **全件を入れる。** キャラ会話は 15 件に絞って残りを `recall` ツールで引かせるが、読む側にはそのツールが無い。
  長さは読む側が後ろから落として詰める(形式 §1 の 5)。
- 並び: キャラ会話の選び方(`_select_memories`)を上限なしに延ばしたもの。
  **直近 5 件を新しい順 → 残りを重要度の高い順**。読む側が前から N 件を取ると、
  キャラ会話が N 件に絞ったときとほぼ同じ顔ぶれになる。
- `when`: `_memory_ages` の結果(「今日」「3日前」)。経過を設定していない作品では付かない。

### voice

- `caption` / `seed` / `refs`(`ref_paths` のファイルを `assets/voices/` から同梱)。
- `preset`(エンジン側の声 ID)と `params`(エンジンへの追加パラメータ)は入れない。エンジンに依存するため。
  `preset` しか持たない声は、カードでは声なし(`voice` を省く)になる。確認ダイアログでその旨を出す。
- 声を割り当てていないキャラクターは `voice` を省く。語り手の声で代用しない
  (朗読では語り手の声で読むが、それは朗読の都合で、本人の声ではない)。

### 同梱するファイルの名前

zip の中では元のファイル名(ハッシュ風の名前)を使わず、役割で付け直す。

- 画像: `images/avatar.<拡張子>`、`images/reference.<拡張子>`
- 参照音声: `voice/ref1.<拡張子>`、`voice/ref2.<拡張子>` …

DB が指しているのにファイルが無い場合は、そのファイルだけ飛ばして書き出しは続け、飛ばしたことを結果で返す。

## 4. バックエンド

新しいモジュール `backend/character_card.py`。読み取り専用で、DB に何も書かない。

```python
def build_card(store, char_id, anchor, label=None, now=None) -> CardBuild:
    """card.json の中身(card)、同梱するファイル(files。zip 内の名前と元のパス)、注意書き(notes)を作る。
    CardBuild.summary() が、確認ダイアログに出す内訳(件数・既定のラベルとファイル名・注意書き)を返す。"""

def write_zip(dest: str, card: dict, files: list[CardFile]) -> dict:
    """<dest>.part に書いてから置き換える。返り値は書いたパスとバイト数。"""

def suggested_name(build: CardBuild) -> str:
    """保存ダイアログの既定のファイル名。<名前>@<シーンのタイトル>.zip"""
```

- `build_card` は SQLite に触るのでイベントループ上で呼ぶ。`write_zip` はファイル IO なので
  `asyncio.to_thread` に逃がす(overview.md §5 の型。バックアップと同じ)。
- 画像・音声は圧縮済みなので `ZIP_STORED`、`card.json` は `ZIP_DEFLATED`。
- `card.json` は `ensure_ascii=False`、インデント 2(人が開いて読めるように)。
- ファイル名に使えない文字(`\ / : * ? " < > |`、制御文字)は `_` に置き換え、長さは 80 字で切る。
- 形式の「無ければ項目ごと省く」を 1 か所で守る(空文字・空配列・`None` を落とす関数を最後に通す)。

### API

| | 入力 | 返すもの |
|---|---|---|
| `GET /characters/{id}/card/preview?anchor=` | | 既定のラベル、既定のファイル名、件数(状況・関係・記憶・画像・参照音声)、声の有無、注意書き |
| `POST /characters/{id}/card/export` | `anchor` / `path` / `label` | 書いたパス、バイト数、飛ばしたファイル |

- 断る場合(400): キャラクターが無い、アンカーのシーンが無い、道が空(シーンが 1 つも無い)、ライブラリが未設定。
- zip の本体は HTTP に流さず、バックエンドが `path` へ直接書く(同じ PC にいるため。バックアップと同じ)。

### chat_agent との共有

`describe_score` / `appearance_hint` / `memory_ages` をカードでも使う。
下線付きのままよそから呼ばないよう、**下線を外して公開の関数にした**(中身は変えていない)。
記憶の並びは、`_select_memories` から「新しい順に取る」「重要度で並べる」を取り出し、
キャラ会話(15 件に絞る)とカード(`memories_by_priority`。全件)の両方から呼ぶ。

## 5. 画面

### 入口

相談チャットのヘッダー。**話す相手にキャラクターを選んでいるときだけ**出す「カード」のボタン
(相談・キャラ同士の会話のときは出さない)。インタビュー / 劇中会話の切り替えの右に置く。

- キャラクターとアンカーが既に選ばれているので、選ぶ画面を新しく作らずに済む。
- その時点の本人と文字で少し話してみて、良ければそのまま書き出す、という流れになる。
- ツールチップ: `「<シーンのタイトル>」までの<名前>をカードに書き出します(ほかのアプリで使う zip)`
- シーンが 1 つも無いときは押せず、ツールチップで理由を出す。
- アイコンだけにせず文字を添えた(ヘッダーの「声 オン / オフ」と同じ形。アイコンだけでは何が書き出されるか伝わらない)。

採らなかった入口:
- **資料庫のキャラクター詳細**: キャラクターの持ち物を扱う場所で自然だが、時点の情報が無く、シーンを選ぶ欄が要る。
  不便が分かったら、あとで入口を足す。
- **キャラクタービュー(出番表)**: 「この時点のキャラクター」を選べるが、目立たず見つけにくい。

### 確認ダイアログ

ボタンを押すとモーダル(`CharacterCardDialog.tsx`)を開き、preview を取る。
部品はスタイルガイドのモーダルの型をそのまま使う。

```
┌ カードに書き出す ───────────────────────────┐
│ この時点のキャラクターを 1 つの zip にまとめ、…      │
│ (アバター) ゆきこ                                    │
│                                                      │
│ 時点の呼び名                                         │
│ [ 「雨の駅」の直後                                 ] │
│                                                      │
│ 入るもの                                             │
│   状況 4 件 / 世間で知られていること 1 件 / 関係 3 人 / 記憶 27 件 │
│   画像 2 枚 / 声 あり(参照音声 1 本)               │
│                                                      │
│ ⚠ 声が割り当てられていません(声なしで書き出します) │
│                                                      │
│                            [ 取り消し ] [ 書き出す ] │
└──────────────────────────────────────────────────────┘
```

- 「時点の呼び名」は `source.label` になる入力欄。読む側の一覧で、同じキャラクターの別の時点と見分けるために使われる。
  空にして書き出すと既定の呼び名になる。
- 注意書きは該当するときだけ出す: 声が未割り当て / 声に説明も参照音声も無い / 画像が無い / ファイルが見つからない。
- 「書き出す」で保存ダイアログ(既定名 `<名前>@<シーンのタイトル>.zip`)→ 保存。
  保存ダイアログを取り消したらモーダルに戻る。
- **終わってもモーダルは閉じない。** その場に保存先と大きさを出し、下端を「フォルダで表示」(`shell:reveal`)と
  「閉じる」に替える。当初は閉じてから通知を出す案だったが、通知(ステータスバーの 5 秒の表示)は
  長いパスを読ませる場所ではなく、「フォルダで表示」を置く場所も無い。外部バックアップの書き出しも結果をその場に出している。
- LLM を使わないので `tasks.ts` のキューには積まない(数秒かからず終わる)。
- 資料庫で編集中の未保存の内容は入らない(保存済みの内容を書き出す)。未保存であることの注意書きは入れていない
  (相談チャットから資料庫の編集状態を見る口が無いため。困ったら足す)。

### メインプロセス

- `card:chooseSaveFile(defaultName, defaultDir)` を足す(`backup:chooseSaveFile` と同じ形。題名とフィルターだけ違う)。
- 既定のフォルダは前回の書き出し先。レンダラが `localStorage.cardExportDir` に覚える。無ければドキュメント。
- バージョンは `STORY_GRAPH_APP_VERSION` でバックエンドへ渡す(`STORY_GRAPH_APP_DATA` と同じ渡し方)。

## 6. 汎用性について

2026-11-10 のユーザーの方針: 音声会話だけでなく、将来ほかのアプリにも渡せる形にする。
そのために形式と書き出しで守ること。

- **読む側の名前や都合を、形式にも書き出しにも入れない。** 文字数の上限、プロンプトの組み立て、
  話し相手が誰かは、すべて読む側が決める。story-graph 側に「音声会話用」の分岐を作らない。
- **素材は削らずに渡す。** 記憶は全件、画像と参照音声は元のファイルのまま。要る分だけ読む側が使う。
- **内部の尺度は言葉にして渡す。** 関係値や重要度の数値は、並び順と文章に変える。
- **`card.json` だけで成り立つ。** 画像や声を扱えない読む側(文字だけのチャットなど)は、JSON だけ読めばよい。

採らなかった案:
- **既存のキャラクターカード形式(SillyTavern などで使われる Character Card V2)をそのまま使う**:
  読めるアプリは多いが、時点・画像の役割・声を持つ場所が無く、項目が特定の会話アプリのプロンプト構成に寄っている。
  独自の形式を正にして、必要になったら変換を足す(カードの `profile` / `appearance` / `situation` / `examples` から作れる)。
- **読む側が story-graph の API を直接呼ぶ**: 常に最新になるが、両方の起動が要り、読む側が story-graph の内部に縛られる。

## 7. 検証

`backend/tests/test_character_card.py`(一時ライブラリ。ユーザーのライブラリには触れない)。

- 項目が §3 の表どおりに入る。空の項目は省かれる。
- 道より先のシーンの記憶・関係・facts が入らない。別の時点で書き出すと中身が変わる。
- 他のキャラクターの `profile` が入らない。`appearance` は 60 字で切れる。
- 関係に数値が入らず、絶対値の大きい順に並ぶ。削除済みの相手は省かれる。
- 記憶が全件入り、直近 5 件 → 重要度順に並ぶ。経過を設定した道では `when` が付く。
- 声: 説明・seed・参照音声が入る。`preset` だけの声と未割り当ては `voice` を省き、注意書きが返る。
- zip: `card.json` が直下にあり、参照しているファイルがすべて入っている。無いファイルは飛ばして結果に載る。
- 書き出しの前後で DB の内容が変わらない。
- 断る場合の 400。

画面は `data/test/` に作った隔離ライブラリで起動して確かめる
(`env -u ELECTRON_RUN_AS_NODE npx electron scripts/check-workspace-ui.cjs --card`。先に build が要る)。
ボタンの出し分け、ダイアログの中身、保存先を選ばなかったとき、書き出した zip の中身、「フォルダで表示」、閉じ方を見る。
保存先を選ぶ窓と「フォルダで表示」は、検証の中で差し替えている。

## 8. 段階 2(あとで設計する)

段階 1 のカードで実際に話してみてから決める。いま分かっている論点だけ残す。

- `summary`: 状況・関係・記憶から、いまの本人を 400 字ほどにまとめる。材料は本人が知っていることだけ。
- `examples`: 清書から本人の台詞を拾う。朗読台本(話者つき)があればそこから取れる。無いシーンは鉤括弧からの推定になり、
  話者を取り違えうる。道の上の清書だけを対象にする。
- どちらも LLM を使うので、`tasks.ts` のキューに積み、SSE で進捗を返し、途中で止められるようにする。
  プロンプトは設定画面で編集できるものに加える(system-prompts.md)。
- 作った `summary` / `examples` を保存して使い回すか、毎回作るか。保存するなら置き場と stale の扱いが要る。
